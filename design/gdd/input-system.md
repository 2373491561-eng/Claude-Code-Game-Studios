# 输入系统

> **Status**: Approved
> **Author**: user + agents
> **Last Updated**: 2026-05-08 (design-review — input processing architecture note, AC precision fix)
> **Creative Director Review (CD-GDD-ALIGN)**: Skipped — Lean mode
> **Implements Pillar**: 间接服务于闪避即武器(P1)、每一枪都要有感觉(P2)

## Overview

输入系统是玩家与《裂隙反应》之间的第一道桥梁。玩家通过键盘和鼠标发出每一个指令——WASD 的八方向移动、鼠标指向的瞄准方向、Shift/右键的双通道闪避、鼠标左键的持续射击——输入系统将这些物理动作即时转化为游戏内的行动信号。它不创造玩法，但它的即时性和精确性定义了什么叫做"手感"。在 240fps 的目标帧率下，玩家按下按键到看到角色反应的延迟必须短到不可感知——因为在这个游戏里，一次极限闪避的成败只在一帧之间。

## Player Fantasy

输入系统追求的是"消失感"。当玩家不再意识到自己在"按下 Shift 闪避"而只是"闪避了"，当极限闪避的按下与屏幕上的冷色时间缩放之间没有任何可感知的延迟——输入系统就赢得了它的战斗。它不是玩家享受的对象，但它是所有享受的前提。Shift 和鼠标右键都可以触发闪避——无论玩家是键盘派还是鼠标派，操作习惯被尊重，肌肉记忆被保护。一根手指在正确时刻按下正确按键，角色在一帧之内做出反应——这种"我的身体延伸到了游戏中"的错觉，就是输入系统最根本的幻想。

## Detailed Design

### Core Rules

**输入动作映射表**：

| 动作名称 | 按键 | 输入类型 | 说明 |
|---------|------|---------|------|
| `move` | WASD | 持续（轴输入） | 8方向移动，WASD 组合产生对角线 |
| `aim` | 鼠标位置 | 持续（坐标输入） | 鼠标光标位置 = 瞄准方向 |
| `shoot` | 鼠标左键 | 持续（按住连射） | 按住时每帧或按射速间隔触发 |
| `dodge` | Shift / 鼠标右键 | 瞬间（按下触发） | 双通道绑定，任一按下即触发闪避 |
| `skill_1` | 空格键 | 瞬间（按下触发） | 时间冷却型技能，闪避成功缩短 CD |
| `skill_2` | 无手动按键 | 自动触发 | 极限闪避后，下一次攻击自动附带技能2效果 |
| `pause` | Esc | 瞬间（按下触发） | 打开暂停菜单 |

**输入优先级**：
1. `pause` 最高优先级——任何状态下 Esc 立即暂停
2. `dodge` 优先于 `shoot`——闪避期间不触发射击
3. `skill_1` 与 `shoot` 可同时——技能释放不中断射击
4. `skill_2` 自动触发不占用输入通道——在闪避后的首次攻击中自动附加

**双通道闪避逻辑**：Shift 和鼠标右键绑定同一 `dodge` 动作。任一按下触发闪避，同时按下不重复触发。闪避期间再次按下不重复触发（必须等闪避动画结束）。

### States and Transitions

| 状态 | 允许的输入 | 说明 |
|------|-----------|------|
| **正常** | 全部 | 玩家自由移动、射击、闪避、技能 |
| **闪避中** | `aim`（方向锁定）、`skill_1` | 闪避动画期间锁定移动和射击，不锁定技能1 |
| **技能释放中** | `aim`、`dodge` | 技能动画期间可闪避取消（能力取消窗口） |
| **暂停** | 仅 `pause`（恢复） | 所有游戏输入冻结 |
| **死亡** | 无 | 等待结算画面出现后恢复菜单输入 |

### Interactions with Other Systems

| 目标系统 | 数据流向 | 接口 |
|---------|---------|------|
| 玩家移动（C1） | 输入 → 移动 | `move` 动作的轴值（Vector2：x=-1..1, y=-1..1） |
| 射击系统（C2） | 输入 → 射击 | `shoot` 按下状态（bool）+ `aim` 方向（Vector2） |
| 闪避系统（C3） | 输入 → 闪避 | `dodge` 触发信号（瞬间 true）+ 闪避方向 = 当前移动方向或最后移动方向 |
| 技能系统（C4） | 输入 → 技能 | `skill_1` 触发信号；`skill_2` 由闪避系统通知技能系统自动触发 |
| 菜单系统（P5） | 输入 → 菜单 | `pause` 触发信号 |

## Formulas

输入系统本身不涉及数学公式。输入缓冲窗口和闪避双通道的去抖时间是仅有的数值参数，见 Tuning Knobs。

**输入处理架构**：所有游戏输入信号（`dodge`, `skill_1`, `shoot`）统一在 `_physics_process` 中通过 `Input.is_action_just_pressed()` / `Input.is_action_pressed()` 检测——而非分散在 `_input()` 和 `_physics_process` 之间。这保证同帧事件优先级可控（技能系统 GDD v3 的 AC7 依赖此架构）。`_input(event)` 仅用于去抖和缓冲的状态标记（轻量，不触发动作执行）。

## Edge Cases

- **同时按下 Shift + 右键**：只触发一次闪避，去抖窗口内（≤50ms）的重复信号合并为一次
- **闪避期间连按闪避键**：被忽略——必须等闪避动画结束（300ms）才能再次触发。闪避结束前 100ms 内的按下进入输入缓冲（100ms 缓冲窗口），动画结束后自动触发下一次
- **按住射击时按下闪避**：射击立即中断，闪避优先。闪避结束后若射击键仍按住，自动恢复射击
- **WASD 同时按下两个相反方向**（如 W+S）：取最新按下的方向——S 覆盖 W
- **极限闪避后 0.5 秒内无攻击**：skill_2 自动触发窗口关闭，本次 skill_2 机会丢失
- **暂停状态下按下 Esc**：恢复游戏，不触发其他动作
- **Alt+Tab 切出窗口**：自动暂停（等同于 Esc），切回后保持暂停状态

## Dependencies

- **上游依赖**：无（基础层）
- **下游系统**：玩家移动 C1、射击系统 C2、闪避系统 C3、技能系统 C4、菜单系统 P5
- **依赖性质**：单向——输入系统只负责发出信号，不关心信号被如何处理

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 说明 |
|------|-------|---------|------|
| 闪避去抖窗口 | 50ms | 30-100ms | 低于30ms可能漏掉合法双击，高于100ms感觉迟钝 |
| skill_2 自动触发窗口 | 500ms | 300-800ms | 极限闪避后多长时间内的下一次攻击触发 skill_2 |
| 输入缓冲窗口 | 100ms | 50-200ms | 允许玩家在动作结束前提前按下，动作完成后立即执行 |

## Visual/Audio Requirements

输入系统本身不产生视觉或音频——它发送信号，由接收系统负责表现。但输入系统可以通过以下方式间接贡献视觉/音频反馈：

- **输入延迟透明度**：输入到动作的延迟应低到不可感知（<16ms，即 240fps 下 1 帧以内）。这是"手感"的物理底线。
- **按键提示 HUD**：在教程或首次出现时，可在角色附近显示浮动按键提示（如 "[Shift/右键] 闪避"），由 HUD 系统负责渲染。
- **输入冲突时的音效处理**：如果玩家在闪避期间按闪避键（无效输入），不产生错误音效——沉默比"叮叮叮"更好。

## UI Requirements

输入系统不拥有 UI 界面——按键配置和暂停菜单属于设置系统（PL2）和菜单系统（P5）。输入系统仅定义以下 UI 相关需求：

- **按键提示**：首次进入游戏时，在 HUD 上短暂显示核心按键提示（WASD 移动、左键射击、Shift/右键闪避、空格技能、Esc 暂停），3 秒后自动淡出
- **暂停菜单入口**：Esc 调用暂停菜单，菜单的视觉设计和布局由菜单系统负责
- **按键冲突提示**：如果检测到两个动作绑定到同一按键（未来支持自定义绑定时），需要警告提示

## Acceptance Criteria

- **GIVEN** 玩家按下 W，**WHEN** 角色处于正常状态，**THEN** 角色向上移动（Vector2 y=-1）
- **GIVEN** 玩家同时按下 W 和 D，**WHEN** 角色正常，**THEN** 角色向右上对角线移动
- **GIVEN** 玩家按住鼠标左键，**WHEN** 角色正常且可射击，**THEN** 按射速间隔（125ms，8 发/秒）连续射击
- **GIVEN** 玩家按下 Shift，**WHEN** 角色正常且闪避充能可用，**THEN** 角色向当前移动方向闪避
- **GIVEN** 玩家按下鼠标右键，**WHEN** 角色正常且闪避充能可用，**THEN** 同上——Shift 和右键效果完全相同
- **GIVEN** 玩家同时按下 Shift 和右键，**WHEN** 角色正常，**THEN** 只触发一次闪避（去抖）
- **GIVEN** 玩家按住射击时按下闪避，**WHEN** 闪避结束且射击键仍按住，**THEN** 射击自动恢复
- **GIVEN** 玩家按下 Esc，**WHEN** 游戏中任意时刻，**THEN** 游戏立即暂停
- **GIVEN** 极限闪避成功后，**WHEN** 玩家在 500ms 内进行下一次攻击，**THEN** skill_2 效果自动附加
- **GIVEN** 玩家 Alt+Tab 切出，**WHEN** 游戏失去焦点，**THEN** 自动暂停

## Open Questions

- **手柄支持范围**：当前设计仅覆盖键盘/鼠标。手柄支持（左摇杆移动、右摇杆瞄准、扳机射击、A/RT闪避）作为 Tier 2 内容，MVP 不要求。是否需要预留手柄输入映射的扩展点？
- **按键自定义**：MVP 阶段是否允许玩家重新绑定按键？当前设计假设固定映射，但代码中应使用 Input Map 而非硬编码按键检测——这已是 Godot 的默认做法。
- **双击闪避**：部分玩家可能期望快速双击方向键触发闪避。MVP 阶段不做，但标记为可能的扩展方向。
