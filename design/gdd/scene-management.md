# 场景管理

> **Status**: Approved
> **Author**: user + agents
> **Last Updated**: 2026-05-08 (design-review — tolerance fixes, cross-reference to damage-health GDD)
> **Creative Director Review (CD-GDD-ALIGN)**: Skipped — Lean mode
> **Implements Pillar**: 压迫与释放（P4）— 场景在常态和释放之间的视觉上下文

## Overview

场景管理系统负责《裂隙反应》中所有场景的加载、切换和生命周期管理。游戏包含三个核心场景：主菜单（工业冷蓝基调的入口）、战斗场景（废弃化工园区，唯一承载全部玩法的场景）和死亡结算画面（暖暮余烬的过渡）。场景切换在菜单→战斗→结算之间流动，而波次过渡和升级选择在战斗场景内部完成——不需要重新加载场景。它的技术目标是确保场景切换干净、快速、无残留，让玩家体验的是从一个状态到另一个状态的自然过渡，而不是"正在加载"的等待感。

## Player Fantasy

场景管理的幻想就是"不存在"。当玩家点击"开始"后直接进入化工厂的战斗——没有加载条、没有黑屏等待——场景管理就赢了。三个场景之间的流动是自然的呼吸：菜单是吸气的期待（冷蓝），战斗是憋气的紧张（灰蓝→侵蚀紫红），死亡结算是呼气的余韵（暖暮琥珀）。玩家感受的不是场景在切换，而是情绪在流动。

## Detailed Design

### Core Rules

**场景清单**：

| 场景 | 文件名 | 用途 | 包含内容 |
|------|--------|------|---------|
| 主菜单 | `main_menu.tscn` | 游戏入口 | 标题、开始按钮、背景（工业冷蓝） |
| 战斗场景 | `game.tscn` | 核心玩法 | 化工厂环境、玩家角色、敌人管理器、VFX层、Diegetic UI、HUD、升级卡片 |
| 死亡结算 | `death_screen.tscn` | Run 结束过渡 | 本局统计、返回按钮、背景（暖暮琥珀） |

**场景切换流**：

```
主菜单 ──(开始游戏)──→ 战斗场景 ──(死亡)──→ 死亡结算 ──(返回)──→ 主菜单
```

- 主菜单 → 战斗：加载 `game.tscn`，初始化新 Run
- 战斗 → 死亡结算：携带本局统计数据（波次、击杀、构筑选择）
- 死亡结算 → 主菜单：释放战斗场景资源，回到入口

**战斗场景内部不切换场景**：
- 波次过渡：在当前场景内完成（暗角加深 → 卡片出现 → 选择 → 下一波）
- 场景状态变化（侵蚀推进、照明阶段切换）：在当前场景内通过节点属性控制

**Autoload 单例**：
- `GameManager`：跨场景保持 Run 状态（当前波次、构筑选择记录、统计数据）
- `AudioManager`：跨场景保持音频（背景音乐无缝过渡）

### States and Transitions

| 场景 | 状态 | 触发 | 说明 |
|------|------|------|------|
| 主菜单 | 空闲 | 游戏启动 | 等待玩家操作 |
| 主菜单 | 过渡中 | 点击"开始" | 短暂过渡（< 500ms），加载战斗场景 |
| 战斗场景 | 加载中 | 进入场景 | 初始化环境、角色、首波敌人 |
| 战斗场景 | 战斗中 | 加载完成 | 常态战斗循环 |
| 战斗场景 | 波次过渡 | 清完一波 | 暗角 + 卡片 UI，不切换场景 |
| 战斗场景 | 死亡 | 血量归零 | 冻结战斗 → 记录统计 → 切换到死亡结算 |
| 死亡结算 | 展示 | 进入场景 | 统计数据逐个浮现 |
| 死亡结算 | 过渡中 | 点击"返回" | 切换到主菜单 |

### Interactions with Other Systems

| 目标系统 | 数据流向 | 接口 |
|---------|---------|------|
| 敌人系统（C6） | 场景 → 敌人 | 战斗场景提供敌人生成锚点（SpawnPoint 节点） |
| 波次管理（F6） | 场景 → 波次 | 战斗场景持有波次管理器节点，控制波次推进 |
| 菜单系统（P5） | 场景 ← → 菜单 | 主菜单和死亡结算场景承载菜单 UI |
| GameManager（Autoload） | 场景 ↔ GM | 场景加载时读取 GM 状态，死亡时写入 GM 统计 |

## Formulas

场景管理系统不涉及数学公式。场景切换的过渡时间见 Tuning Knobs。

## Edge Cases

- **战斗中 Alt+F4 关闭游戏**：GameManager 不做保存——Roguelike Run 本身不持久化，下一次启动回到主菜单
- **场景切换期间按下 Esc**：忽略——过渡期间不接受输入
- **战斗场景加载失败**（资源缺失）：显示错误提示并回到主菜单——不能卡在黑屏
- **同一场景连续快速切换**（如玩家连点"返回"）：加去抖——切换触发后 500ms 内忽略同一切换请求
- **死亡结算时 Alt+Tab 切出再切回**：保持结算画面——状态不丢失

## Dependencies

- **上游依赖**：无（基础层）
- **下游系统**：敌人系统 C6、波次管理 F6、菜单系统 P5
- **Autoload 依赖**：GameManager（跨场景状态）、AudioManager（跨场景音频）
- **依赖性质**：场景管理提供容器，子系统在容器内运行

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 说明 |
|------|-------|---------|------|
| 场景切换过渡时间 | 300ms | 200-500ms | 淡入淡出动画时长 |
| 场景切换去抖窗口 | 500ms | 300-1000ms | 防止快速连点导致多次切换 |
| 死亡冻结时间 | 500ms | 300-800ms | 死亡后到结算画面出现的间隔（与伤害系统 GDD 对齐） |

## Visual/Audio Requirements

场景管理本身不产生视觉或音频——它负责场景之间的过渡。过渡动画的元素由各自场景提供：

- **菜单→战斗过渡**：主菜单快速淡出（200ms），战斗场景从黑底淡入（300ms）。无加载画面。
- **战斗→死亡过渡**：战斗画面冻结（时间缩放归零，500ms），然后交叉淡入淡出切换到暖暮琥珀结算画面。
- **跨场景音频**：AudioManager 保持背景音乐在场景切换之间不断——淡入淡出交接，不是硬切。

## UI Requirements

场景管理不拥有 UI，但它定义了 UI 出现的位置：

- 主菜单场景承载菜单 UI（P5 负责）
- 战斗场景承载 Diegetic UI（P2）+ HUD（P3）+ 升级卡片（P4）
- 死亡结算场景承载统计展示 UI（P5 负责）
- 战斗中**没有"暂停菜单"**——Esc 只支持最小暂停（冻结画面 + "继续/退出"两个选项）

## Acceptance Criteria

- **GIVEN** 玩家在主菜单，**WHEN** 点击"开始"，**THEN** 300±50ms 内过渡到战斗场景且角色可操作（WASD 移动响应）
- **GIVEN** 玩家在战斗中死亡，**WHEN** 血量归零，**THEN** 战斗冻结 500±50ms 后切换到死亡结算画面（与伤害系统 GDD AC2 对齐）
- **GIVEN** 玩家在死亡结算画面，**WHEN** 点击"返回"，**THEN** 回到主菜单
- **GIVEN** 一场新 Run 开始，**WHEN** 战斗场景加载，**THEN** 上一局的敌人、粒子、UI 全部清空
- **GIVEN** 波次过渡触发，**WHEN** 清完当前波所有敌人，**THEN** 不切换场景——在当前场景内弹出升级卡片
- **GIVEN** 战斗场景加载失败（资源缺失），**WHEN** 加载出错，**THEN** 显示错误提示并回到主菜单

## Open Questions

- **场景切换性能**：960×540 像素场景的加载在 PC 上应在 100ms 内完成——Godot 同步加载是否满足？如果场景资源增加（Tier 2 更多装饰），是否需要预加载？
- **暂停菜单深度**：当前只支持"继续/退出"——是否需要"返回主菜单并保存进度"？这会影响跨局进度系统（F7）的设计。
- **战斗场景重置**：每次新 Run 是重新加载 `game.tscn`，还是在当前场景内重置所有节点？前者更干净但切换开销大，后者更快但需要确保所有状态都重置到位。
