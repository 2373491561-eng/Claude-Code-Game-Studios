# 跨局进度

> **Status**: Approved
> **Author**: user + agents
> **Last Updated**: 2026-05-07

## Overview

跨局进度系统管理玩家在多次 Run 之间的成长——基于每局表现获得点数，解锁新武器、新技能类型、新增升级选项加入随机池。死亡不是终点——它是解锁更多可能性的钥匙。进度持久化由存档系统（PL1）负责。

## Player Fantasy

跨局进度追求的是"每次失败都在为下一次胜利铺路"。死亡不会让你沮丧——结算画面告诉你"你又解锁了新东西"，回到主菜单时你知道下一局有了更多可能。这不是惩罚循环——这是成长循环。

## Detailed Design

**点数获取**：每局结束后，根据表现计算：击杀数 × 0.1 + 波次数 × 1 = 点数

**解锁内容**：点数达到阈值解锁新内容加入随机池。

| 解锁 | 点数需求 | 内容 |
|------|:---:|------|
| 射速 +15% 升级 | 5 | 构筑池新增该选项 |
| 第二把武器 | 15 | 可选起始武器 |
| 技能 1 CD -5s 升级 | 25 | 构筑池新增 |
| 技能 2 伤害翻倍升级 | 40 | 构筑池新增 |
| 闪避充能 +1 升级 | 60 | 构筑池新增 |

**流程**：死亡 → 结算画面 → 计算点数 → 检查解锁 → 玩家回到主菜单（新内容已可用）

## Formulas

### 点数计算

```
points = floor(kills × 0.1 + wave_reached × 1)
```

| 变量 | 类型 | 范围 | 说明 |
|------|------|------|------|
| kills | int | 0-N | 本局总击杀数 |
| wave_reached | int | 1-N | 死亡时所在波次 |

**示例**：波次=3，击杀=20 → `floor(2.0 + 3.0) = 5` 点

## Edge Cases

- **首局即死亡（波次=1，击杀 < 5）**：floor(0.x + 1) = 1 点——至少给 1 点，不让玩家有空手而归的感觉
- **点数刚好跨过多个解锁阈值**：顺序解锁——结算时按点数从低到高依次检查
- **存档损坏/不存在**：进度归零，重新开始——不影响核心游戏

## Dependencies

- **上游依赖**：波次管理 F6（波次数据）
- **下游依赖**：存档 PL1（持久化）、构筑系统 F5（解锁池扩展）

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 说明 |
|------|-------|---------|------|
| 击杀系数 | 0.1 | 0.05-0.2 | 每击杀换点数 |
| 波次系数 | 1 | 1-3 | 每波换点数 |
| 解锁阈值 | 5/15/25/40/60 | 可调 | 各解锁的点数门槛 |

## Acceptance Criteria

- **GIVEN** 第 1 局死亡（波次=3，击杀=20），**WHEN** 结算，**THEN** 获得 5 点数，解锁"射速 +15%"升级
- **GIVEN** 解锁后，**WHEN** 下一局开始，**THEN** 新升级出现在构筑随机池中
